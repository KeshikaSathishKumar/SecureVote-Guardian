About SecureVote Guardian

The Problem

Traditional online voting systems have a fatal flaw: the server operator can see every vote. A compromised or malicious admin can alter results, and there is no way for voters to verify their vote was counted correctly without exposing their choice.

Our Solution

SecureVote Guardian uses client-side encryption so the server never sees plaintext votes. A threshold decryption scheme means no single person can unilaterally decrypt results. Every action is logged in a tamper-evident audit trail.

🔐 Cryptographic Method

Custom Threshold Paillier Homomorphic Encryption + Shamir's Secret Sharing

  • The server can add encrypted votes together without ever decrypting them (homomorphic addition).
  • The private decryption key is split across n trustees using Shamir's Secret Sharing.
  • A minimum quorum (threshold) of trustees must cooperate to reconstruct the key and reveal results.
  • Voters receive a cryptographic receipt to verify their vote was included.

Security Guarantees

🛡️ Privacy — Individual votes never revealed
✅ Integrity — Encrypted votes cannot be altered
🔍 Verifiability — Receipts + audit log
🔑 No single point — Threshold key splitting

Technical Stack

  • Backend: Python 3 + Flask + SQLAlchemy (SQLite)
  • Crypto: Pure Python Paillier HE + Shamir Secret Sharing (no external libs)
  • Frontend: Vanilla HTML/CSS/JS with BigInt for client-side encryption
